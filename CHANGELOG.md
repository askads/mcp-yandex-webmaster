# Changelog

Все заметные изменения проекта документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/),
проект придерживается [семантического версионирования](https://semver.org/lang/ru/).

## [1.1.0] — 2026-08-19

### Добавлено

- Подключение прямо из диалога, без правки конфигурации и без перезапуска клиента:
  `start_login` выдаёт ссылку на Яндекс OAuth, `finish_login` меняет код подтверждения
  на токен и сразу проверяет его живым запросом (заодно лениво определяя `user_id`).
  Дополняют пару `auth_status` (откуда взят токен, когда истекает, где лежит файл)
  и `logout`.
- Схема входа — OAuth с PKCE (S256) и `redirect_uri=https://oauth.yandex.ru/verification_code`.
  `code_verifier` не покидает процесс, поэтому в переписку попадает только одноразовый
  код, живущий 10 минут: без верификатора он бесполезен, в отличие от самого токена.
  Секрет приложения не используется вовсе — сервер работает как публичный клиент,
  и класть `client_secret` в npm-пакет не требуется.
- Токен хранится в `~/.config/mcp-yandex-webmaster/credentials.json` с правами `0600`,
  вместе с `refresh_token`: истёкший доступ переоформляется молча, в том числе после
  ответа 401 от API. Битый или обрезанный файл читается как «не подключено», а не как
  пустой токен.
- Запрос прав сужен явно: `scope=webmaster:hostinfo webmaster:verify` и `force_confirm=yes`.
  Без `scope` Яндекс выдаёт токен со всеми правами приложения, а `force_confirm` не даёт
  вернуть ранее выданный токен с более широким набором.
- Переменная `YANDEX_WEBMASTER_OAUTH_CLIENT_ID` — вход через своё OAuth-приложение.
- Событие телеметрии `unconfigured_start` (с прежним закрытым словарём причин): сервер без
  токена теперь доживает до MCP-хендшейка, поэтому деградированный старт считается отдельно,
  не раздувая `server_start` и не умирая как `startup_failed`. `startup_failed` остаётся для
  невалидных значений конфигурации и отправляется fire-and-forget — процесс больше не ждёт
  пинг перед выходом.

### Изменено

- **Сервер больше не завершается из-за конфигурации.** При отсутствии токена он стартует,
  отвечает на `initialize` и `tools/list`, а в `instructions` объясняет оба пути подключения:
  `start_login` прямо в диалоге или `YANDEX_OAUTH_TOKEN` в конфигурации клиента с
  перезапуском. Ошибка «нет токена» возвращается при вызове инструмента
  (`AuthRequiredError`, ответ с `isError`) — до ретраев, автоопределения `user_id` и
  обращения к сети; класс `CredentialsError` заменён на него. Невалидный `YANDEX_USER_ID`
  по-прежнему даёт `ConfigError` (`invalid_user_id`), но процесс выживает: текст проблемы
  уезжает в `instructions`, а не убивает сервер до хендшейка.
- `YANDEX_OAUTH_TOKEN` стала необязательной. Заданная — имеет приоритет над сохранённым
  входом; сервер такой токен не обновляет и не удаляет.
- Токен резолвится на каждом запросе, а не кешируется в клиенте — это то, что позволяет
  `finish_login` подействовать в текущей сессии; `user_id` определяется лениво при первом
  успешном вызове, поэтому вход из диалога не требует перезапуска и для него.

## [1.0.1] — 2026-08-12

### Добавлено

- Инструкции сервера. В ответе MCP `initialize` теперь едет короткая справка для вызывающей
  модели: чем этот API является и чем не является, чего он не умеет, а также квоты, правила
  повторов и обманчивые ошибки, влияющие на то, как им пользоваться. Раньше это знание жило
  только в README, который модель не читает.

## [1.0.0] — 2026-08-11

### Изменено

- Объявлен стабильным. Набор инструментов, схемы входных данных и переменные окружения версии
  0.1.x переносятся без изменений — релиз фиксирует стабильность API, а не новое поведение.

## [0.1.0] — 2026-08-09

### Добавлено
- Первый рабочий релиз (вместо npm-заглушки 0.0.1). MCP-сервер для Yandex Webmaster
  API v4 (OAuth-токен, авто-определение `user_id` через `GET /v4/user` с кешем),
  16 инструментов:
  - сайты и права: `get_user_id`, `list_sites`, `add_site`, `get_site_summary`,
    `get_verification_status`, `start_verification`, `get_site_diagnostics`;
  - поисковые запросы: `get_popular_queries`, `get_search_queries_history`;
  - индексация и sitemap: `get_indexing_history`, `recrawl_url`,
    `list_important_urls`, `list_sitemaps`, `add_sitemap`;
  - ссылки: `get_external_links`;
  - escape hatch: `raw_request` (GET/POST/DELETE, подстановка `{user-id}`,
    SSRF-гард на относительные пути).
- Ретраи с бэкоффом (учёт `Retry-After`): 429 — кроме `QUOTA_EXCEEDED` (суточную
  квоту переобхода бэкофф не вернёт), 5xx/сетевые — только для чтения (запись
  после 5xx не дублируется); таймаут покрывает и чтение тела;
  `WebmasterError(status, body)` с разбором `{error_code, error_message}` и
  подсказками для `HOST_NOT_VERIFIED` / `HOST_NOT_LOADED` / `HOST_NOT_INDEXED` /
  `QUOTA_EXCEEDED`.
- Аннотации на каждом туле: `READ_ONLY` / `WRITE` (создающие операции) /
  `DESTRUCTIVE` (`raw_request` — через него доступны DELETE-ручки).
- Анонимная телеметрия использования (`server_start`, `tool_call`,
  `startup_failed`; отключение `ASKADS_TELEMETRY=0`).
- Тесты: клиент (маппинг wire-значений, кеш user_id, ретраи, таймаут, SSRF),
  тулы, аннотации (закреплённая карта тул → хинты), конфиг (reason-коды),
  телеметрия и dist-smoke с реальным MCP-хендшейком по stdio.
- Документация: README, docs/TOOLS.md, docs/DEVELOPMENT.md, docs/PUBLISHING.md,
  CLAUDE.md; server.json + glama.json; CI (Node 20/22/24) и ежедневный health-check.
